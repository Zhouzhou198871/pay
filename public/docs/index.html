01 · GETTING STARTED

快速开始

完成商户资料准备，了解请求约定，即可开始服务端集成。

接入准备

登录晴天支付商户控制台，进入「个人资料 → API 信息」。在该页面查看已分配的六位商户号，并按接口版本获取对应凭证：

  • V1 API Key：用于 MD5 请求签名。仅保存在商户服务端，不得写入网页、移动端或公开仓库。
  • V2 RSA 密钥：商户私钥用于请求签名，商户公钥提交平台用于验签；私钥生成或重置时请立即安全备份。
  • 平台回调公钥：用于验证平台异步通知签名（通知投递启用后适用）。
安全提示：API Key、RSA 私钥均属于高敏感凭证。请使用环境变量或密钥管理服务保存，定期轮换，避免记录在日志中。

基础说明

API 基础地址https://pay.lynli.me
传输协议HTTPS · TLS
字符编码UTF-8
时间戳Unix 秒级时间戳

当前已部署的 V1、V2 下单接口均要求 Content-Type: application/json，请求体为 JSON 对象。平台内部部分上游通知接口使用 application/x-www-form-urlencoded，但这不代表商户下单接口支持表单格式。所有请求必须通过 HTTPS 从服务端发起。

时间戳与平台时间差不得超过 300 秒。金额单位为 USDT，最多支持 6 位小数；支付类型当前接受 alipay 或 alipay_h5（以通道开放状态为准）。

02 · AUTHENTICATION

签名规范

签名必须在商户服务端生成。签名原文的字段和值必须与实际提交内容一致。

V1 · MD5 签名

V1 使用商户 API Key 参与 MD5 摘要。按以下规则生成签名原文：

  1. 排除 sign 字段，以及值为 null、undefined 或空字符串的字段。
  2. 参数名按 ASCII 字典序升序排列。
  3. 按 key=value 拼接，字段之间使用 &。
  4. 末尾追加 key=商户API_KEY，再以 UTF-8 计算 MD5，输出 32 位十六进制大写字符串。
NODE.JS · MD5
import crypto from "node:crypto";

function signV1(params, apiKey) {
  const canonical = Object.entries(params)
    .filter(([key, value]) => key !== "sign" && value != null && String(value) !== "")
    .sort(([a], [b]) => a < b ? -1 : a > b ? 1 : 0)
    .map(([key, value]) => key + "=" + value)
    .concat("key=" + apiKey)
    .join("&");
  return crypto.createHash("md5").update(canonical, "utf8").digest("hex").toUpperCase();
}

V1 下单当前要求 JSON，参数 pay_type 为必填；签名函数会过滤空值。不要将 API Key 发送给客户端。

V2 · RSA2 签名

V2 使用商户 RSA 私钥执行 SHA256withRSA（RSASSA-PKCS1-v1_5 + SHA-256），签名结果使用标准 Base64 编码。

  1. 取请求参数并排除 sign 字段；其余标量字段参与签名。
  2. 按参数名 ASCII 字典序升序排列。
  3. 使用 key=value 与 & 拼接，不额外 URL 编码。
  4. 使用商户私钥进行 SHA256withRSA 签名，并将结果 Base64 编码。
NODE.JS · RSA2
import { createSign } from "node:crypto";

function signV2(params, privateKeyPem) {
  const canonical = Object.entries(params)
    .filter(([key]) => key !== "sign")
    .sort(([a], [b]) => a < b ? -1 : a > b ? 1 : 0)
    .map(([key, value]) => key + "=" + value)
    .join("&");
  const signer = createSign("RSA-SHA256");
  signer.update(canonical, "utf8");
  signer.end();
  return signer.sign(privateKeyPem, "base64");
}

平台使用商户公钥验证请求签名。平台异步通知将使用平台独立密钥签名；商户应使用「API 信息」中的平台公钥验签。商户私钥与平台私钥不可混用。

03 · API REFERENCE

API 接口

所有接口均以 API 基础地址为前缀。请求示例中的签名均为占位值。

统一下单

POST
/api/v1/payments V1 · MD5

创建一笔新的支付订单。V2 使用 POST /api/v2/payments，请求字段相同，签名算法不同。

字段类型必填说明
merchant_noString是六位商户号
out_trade_noString是商户订单号，1–64 位，同一商户不可重复
amountDecimal是USDT 金额，大于 0，最多 6 位小数
pay_typeString是alipay 或 alipay_h5
notify_urlString是HTTPS 公网通知地址
timestampString是10 位 Unix 秒级时间戳，误差不超过 300 秒
signString是按对应版本规则生成的签名

异步通知（回调）

04 · ERROR HANDLING

状态码与错误处理

建议根据 HTTP 状态码和业务错误码分别处理，并对网络超时采用安全重试策略。

HTTP 状态码

HTTP含义建议处理
201订单创建成功保存平台订单号与结账链接
400请求参数错误、时间戳失效修正参数后重新签名
401商户认证或签名失败检查商户号、密钥和签名原文
409商户订单号重复使用新订单号或查询原订单
415Content-Type 不支持使用 application/json
503服务或支付通道暂不可用稍后重试，避免重复创建
500平台内部错误记录请求时间与订单号并联系支持

业务错误码

错误码说明
MISSING_PARAMETER缺少必要参数
INVALID_CONTENT_TYPE请求必须使用 JSON
TIMESTAMP_EXPIRED时间戳无效或超过 5 分钟
INVALID_MERCHANT商户号格式不正确
INVALID_OUT_TRADE_NO商户订单号格式不正确
INVALID_AMOUNT金额格式或范围不正确
UNSUPPORTED_PAY_TYPE当前支付类型不受支持
INVALID_NOTIFY_URL通知地址必须是 HTTPS 公网地址
SIGNATURE_INVALID签名验证失败

当前下单接口没有独立的“余额不足”错误码；如后续产品开通余额校验或扣费机制，将在接口版本更新时补充。
